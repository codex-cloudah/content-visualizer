# 渲染路径实施指南

完成内容分析（工作流第一至九节）与「方案选型」（第十节）后，按所选路径实施。两条路径：**A. 直接生成图片（生成式图像，默认）**；**B. 确定性渲染兜底（仅内容需逐字准确时）**。

---

## 路径 A：直接生成图片（生成式图像，默认）

适用：以视觉创意主体为主、文字少且不要求逐字精确的内容。**默认路径**，不生成前端网页 / HTML。

### A1. 标题单独生成

- 标题文字**单独生成**，作为独立单元，不与图片内容混排。
- 用第一性原则六步法生成标题（降维换喻 → 配动作对 → 制造落差 → 抽走主体 → 语法留白 → 悬念收口）。
- 标题可单独输出为一张标题图，或作为独立文字单元与内容图分开呈现/交付。

### A2. 编写生成指令

按以下顺序组织一段完整指令：

1. **画布与整体风格**：一句确定画布比例与整体调性（现代信息图 / 简洁杂志风 / 文艺手账风等，由内容主题决定）。
2. **整体布局**：自上而下（或从左到右）的模块顺序，说明每个模块的大致位置与占比。
3. **模块标题与关键短句**：需要呈现的中文文字用中文引号“”包裹，作为内容层的文字。
4. **各模块逐段描述**：按信息层级从高到低描述每个模块的内容、数据表达方式（大数字、进度条、对比条、评分星、时间轴、流程图等）与视觉形式（卡片、标签、分隔线等）。
5. **配色与视觉系统**：统一的主色、辅助色、强调色；字体层级；强调元素的用法。
6. **收尾要求**：文字清晰可读、中文无错别字、避免复杂背景与无关装饰、信息不要溢出页面。

### A3. 编写要点

- 指令中必须包含要呈现的中文文字，且用中文引号“ ”标注（模块标题、关键短句、数字标签等）。
- 需要呈现的数据（比例、评分、数量、时间、对比）直接写进指令对应位置，明确其视觉形式。
- 标题文字单独生成，不并入内容层的生成指令。
- 不要问用户要什么风格；风格由内容决定。
- 比例选择：内容少用 1:1 或 4:5；内容多、分点多用竖版长图（如 3:4、9:16 或更长），优先纵向空间，不压缩文字。
- 不编造原文没有的数据与事实。

### A4. 失败与纠错

- 同一生成动作失败 2 次（数据被篡改 / 标题被替换 / 编号错位 / 整图重绘等）→ 立即切换方案：改走路径 B（确定性渲染兜底）。
- 不反复换提示词重试同一路径。

---

## 路径 B：确定性渲染兜底（仅需逐字准确时）

适用：内容含长文本、精确数据、顺序编号，要求逐字、逐数字、逐编号准确。**仅作兜底**，成品仍直接输出 PNG 图片，不经前端网页交付。

### B1. 标题单独生成

- 标题文字**单独**用确定性渲染输出标题 PNG，作为独立单元，不与图片内容混排。
- 标题文字直接写死在 HTML/SVG 源里，逐字核对。

### B2. 编写 HTML

- 所有文字、数据、编号**直接写死在 HTML 源里**，不经过任何生成式模型，因此天然精确。
- 用统一内联 CSS 建立视觉系统：背景、主色、辅助色、强调色、字体层级（大标题/模块标题/正文）、卡片、圆角、分割线、标签、大数字等。
- 版式按内容量自主决定：内容多用竖版长图（页面自然纵向延展），文字不缩小。
- 顺序编号（①②③ / 1.2.3. / 07/08/09）在 HTML 里按真实顺序书写，不靠模型推测。
- 所有数字、比例、时间、人物、引用必须来自原文；原文没有的不写。

### B3. 渲染前逐字核对

- 打开 HTML 源，把每个数字、标题、编号、引用与原文逐条比对。
- 任何不一致先改 HTML 源，再导出；不要在成品图上打补丁。

### B4. 无头浏览器截图导出 PNG

- 用本地无头浏览器（Chrome/Chromium headless）将 HTML 渲染为图片：
  - 单页：`chrome --headless --screenshot=out.png --window-size=W,H file.html`
  - 长图：先把 body 设为目标画布宽度，按实际内容高度截图（可用 `--screenshot` 全页模式或逐段拼接）。
- **必须等待浏览器进程真正结束后，才能读取/处理截图文件（Windows 尤其关键）**：
  - Windows PowerShell 中，GUI 子系统程序（chrome.exe）用 `&` 或直接调用**不会等待其退出**，截图文件可能尚未写完；此时若紧接着去裁剪/读取，会拿到旧文件或半成品，且随后可能被 Chrome 写出的完整画布覆盖（曾导致交付长图底部残留大量空白）。
  - 正确做法：用 `Start-Process -FilePath chrome -ArgumentList ... -Wait`（或 `-PassThru` 后调用 `WaitForExit()`）等待进程退出；再校验输出文件已存在、尺寸与写入时间稳定，然后才继续后续步骤。其他平台同理：先确认进程退出再读产物。
- **长图画布必须按内容裁剪**：`--window-size` 高度大于实际内容时，PNG 底部会残留整片纯背景空白。截图后检测最后一个非背景色像素行，按内容底部裁剪，仅保留设计预留的少量留白（如底部 padding），再交付。
- 截图后再回看一次成图：确认文字完整、无溢出、无错位、编号连续、数据与 HTML 源一致。
- 通过 `present_files` 交付 PNG。

### B5. 需要改动时

- 直接改 HTML 源里的字/数据/编号，然后重新截图导出，替换旧图。
- 禁止对图文密集的成品图用 image_edit 做局部微调（会整图重绘、文字全乱）。

---

## 路径选择速查

| 判断 | 路径 |
| --- | --- |
| 视觉创意为主、文字少且可近似 | **A 直接生成图片（默认）** |
| 要逐字、逐数字、逐编号精确（长文/数据/序号/引用） | **B 确定性渲染兜底** |
| 标题需要逐字精确 | 标题单独确定性渲染输出标题 PNG，内容走 A 或 B |
| 拿不准 | **A 直接生成图片** |
