# 内容视觉化 · 详细工作流

本文件是本 Skill 的核心规则。收到用户内容后，逐节执行，最终产出可直接阅读、可呈现的视觉成品。

## 〇、环境能力探测（生成前必做，跨平台自适应）

**位置**：读取完整用户内容之后、进入内容理解之前，必须先执行本环节（对应 SKILL.md Step 1.5）。

本 Skill 本质是一套可跨平台复用的规则 Prompt，**不得把工具名写死为某个平台专属**。生成前必须先探测当前模型 / Agent 平台实际可调用的模态能力，再据此选择可行的生成路径。

**探测方式**：查看当前环境可用的工具清单 / 系统能力描述，逐项判断（不凭假设、不编造不存在的工具）：

| 能力类别 | 含义 | 各平台示例（仅示意，勿写死） |
| --- | --- | --- |
| 图像生成 | 能否直接调用生成式图像工具出图 | 豆包 `image_gen`（`seedream`）、OpenAI `dall-e`、Stability 等 |
| 图像编辑 | 能否调用图片编辑工具 | 豆包 `image_edit` 等 |
| 文件交付 | 能否把成品以文件/图片交付给用户 | 豆包 `present_files`、Claude `artifact` 等 |
| 网页渲染 | 能否执行 HTML/SVG 并截图导出 PNG | 无头浏览器 / 页面渲染能力 |

**路径选择**：
- 具备「图像生成」→ **路径 A：生成式直接出图**（默认首选，成品直接为 PNG）；
- 不具备图像生成、但具备「网页渲染 + 文件交付」→ **路径 B：确定性渲染兜底**（HTML/SVG 精确排版 → 截图导出 PNG）；
- 两者都不具备 → **文本交付降级**：直接生成结构化的**文本成品**——用 Markdown 等文本排版呈现信息层级、模块结构、关键数据与结论，**不做图片编辑、不假装出图**，并明确告知用户当前环境为纯文本、产出为文本形式。

**铁则**：探测不到某能力时按「不具备」处理，禁止编造不存在的工具；拿不准时默认走「文本交付降级」，不得假装已出图。后续「内容理解 → 重组 → 提炼 → 标题 → 版式 → 视觉 → 文字」环节与路径选择无关，始终执行；「方案选型（第十节）」在已探测结果上落地。

## 〇·一、不确定问题人工确认核对（读取完完整内容之后）

**位置**：完整读取用户内容之后、进入内容理解之前，必须先执行本环节。

**触发条件**（命中任一即必须人工确认核对，不得跳过）：
- 原文存在歧义、缺失、矛盾或口径不清，且会实际影响成品内容；
- 对原文某处内容存在多种可能解读，不同解读会导致成品出现不同信息；
- 原文信息不足以支撑某个模块，需要外部补充，或需确认是否省略该模块；
- 原文中的分类 / 归属 / 执行方式 / 数据口径 / 时间等关键要素存在不确定或前后不一致。

**执行方式**：
1. 一次性把所有不确定问题列成清单，逐条向用户提问；
2. 对每个问题说明：为何会影响成品、不同可能分别对应什么内容、希望用户如何确认；
3. 用户答复后，**以用户答复为准**继续后续全部环节；用户未答复的问题不得擅自揣测处理；
4. 若用户答复后仍有无法溯源的信息，一律按「宁可不写，不得编造」处理（见下节「事实核对」）。

**边界**：只针对**内容事实**的不确定性向用户确认；**不**就结构 / 版式 / 配色 / 风格 / 标题等设计选择询问用户（这些按本 Skill 自主决定）。

**例外说明**：本环节是本 Skill 唯一的「向用户提问」允许点；除此之外，不询问任何其它问题，直接交付成品。

## 一、内容理解

完整理解输入内容。识别其中实际存在的：事实、观点、数据、分类、层级、对比、因果、时间、步骤、问题、结论、案例以及其他重要信息。

区分：
- 什么是核心信息
- 什么是次要信息
- 什么是补充信息

不要平均分配视觉权重。

## 二、信息重组

不要机械复制原文的段落结构。根据内容之间真实存在的关系重新组织信息：

- 如果原文适合「总览 → 分项 → 细节」就采用这种结构
- 如果适合「问题 → 原因 → 结果」就采用这种结构
- 如果适合「对比 → 差异 → 结论」就采用这种结构
- 如果适合「步骤 → 流程 → 结果」就采用这种结构
- 如果适合「观点 → 证据 → 判断」就采用这种结构

不要强行套用固定模板。结构必须由内容决定。

## 三、信息提炼

保留原始内容中真正有信息价值的内容。删除：重复表达、无意义铺垫、口语化冗余、无法帮助理解的信息。

但是：
- 不要删除关键事实
- 不要改变原意
- **不要虚构数据**
- **不要补充原文没有出现的事实**
- **图上出现的每一个数字、比例、人物、引用、结论都必须能在原文中找到依据；找不到依据的信息一律不写**

如果原文存在明确的数据、比例、评分、数量、时间或对比关系，优先使用视觉方式表达，而不是全部埋在正文中。

### 事实核对（生成前必做）

1. 从原文列出所有计划上图的关键事实与数据，形成清单。
2. 逐条核对：该信息是否在原文中出现？措辞/数值是否一致？
3. 原文没有或记忆不清的内容，直接从清单删除。
4. 只有全部可溯源后，才进入版式设计与成品生成。
5. 走确定性渲染时，把「事实核对」升级为「**渲染前逐字核对**」：源里的每个数字、标题、编号、引用都必须与原文逐一比对一致，再导出成品；不一致必须先改源文件。

## 四、标题生成（第一性原则，单独生成）

标题文字**单独生成**，作为独立单元，不与图片内容混排。采用第一性原则方法：

**第一性原理**：标题的本质功能 = 用最少文字，在最短时间内抓住注意力并传达核心信息。人脑对熟悉信息会自动“略过”，陌生感正是打破这种自动化的手段——让读者重新“看见”内容。因此标题生成靠 **熟悉的元素 × 反常的组合**，而非堆砌形容词。

**六步法（顺序执行）**：

1. **降维换喻** —— 把核心抽象概念翻译成人人熟悉的日常物象。
2. **配动作对** —— 给物象配一对互为对照的动作（建立/完成 ↔ 检查/缺失）。
3. **制造落差** —— 把“已完成”与“始终未发生”并置，形成认知失调。
4. **抽走主体** —— 用“没人”等缺位主语替代责任方，让事件悬置。
5. **语法留白** —— 用转折（“但”）、完成时态、短句节奏收紧句子。
6. **悬念收口** —— 不点破结论，留一个问号驱动阅读。

**自检清单**：字面全懂、组合陌生；信息不失真；留悬念；标题文字与图片内容相互独立。

## 五、信息层级

建立明确的信息层级：

- 核心结论应该最容易被看到
- 重要数据应该具有明显视觉权重
- 模块标题应该能够帮助用户快速定位内容
- 解释文字应该低于标题和核心信息
- 辅助信息应该保持较低视觉权重

让用户即使不逐字阅读，也能够通过「标题 → 核心信息 → 数据 → 模块标题 → 关键词」快速理解内容。

## 六、版式设计

根据内容量和信息关系，自主决定：页面方向、画布比例、页面长度、内容区域、模块数量、模块排列、模块尺寸、间距、留白、对齐方式。

- 不要为了追求固定页面比例而压缩内容
- 不要为了填满页面而增加无意义元素
- 当内容较多时，优先增加合理的纵向空间，而不是缩小文字

## 七、视觉设计

建立一个统一的视觉系统。视觉元素必须服务于信息表达。根据内容需要决定：背景、主色、辅助色、强调色、字体层级、字体粗细、卡片、边框、圆角、分割线、标签、数字、图形、图标以及其他视觉元素。

- 避免无意义装饰
- 避免为了制造「设计感」加入与内容无关的元素
- 避免复杂背景
- 避免视觉效果压过信息本身

## 八、文字处理

不要把原始内容原封不动塞进页面。将文字转换为适合视觉阅读的形式：

- 模块标题应该具有识别作用
- 正文尽可能使用短句
- 重要信息可以单独突出
- 标题文字已在「标题生成」环节单独生成，不在本环节重复处理
- **语言**：无论原始内容是什么语言，成品中的标题、正文、数据说明、标签、编号一律用中文；专有名词、品牌名、必要英文缩写可保留原文

必要时使用：数字、标签、关键词、短句、列表、卡片、评分、对比、流程、关系结构。但只有在内容确实适合时才使用。

## 九、视觉阅读路径

整个成品应该形成自然的阅读顺序：

1. 第一眼看到最重要的信息
2. 第二眼理解整体结构
3. 第三眼查看关键细节
4. 最后能够得到完整结论

不要让所有元素争夺注意力。不要让页面出现多个无法判断优先级的视觉中心。

## 十、方案选型（在能力探测结果上落地）

**前置**：已按「〇、环境能力探测」判定当前环境可调用的模态能力，本节在此基础上选择并落地渲染路径。

### 判定规则

| 内容特征 | 渲染路径 |
| --- | --- |
| 当前环境具备**图像生成**能力 | **路径 A 直接生成图片**：使用当前平台实际可调用的图像生成工具（如豆包 `image_gen` + `seedream_5.0_pro`），成品直接为 PNG |
| 不具备图像生成、但具备**网页渲染 + 文件交付** | **路径 B 确定性渲染兜底**：HTML/SVG 精确排版 → 无头浏览器截图导出 PNG（成品仍为图片，不经前端网页交付） |
| 两者都不具备 | **文本交付降级**：直接生成文本成品（Markdown 等文本排版呈现信息层级与结构），不做图片编辑，明确告知产出为文本形式 |
| 标题需要逐字精确 | 标题**单独**用确定性渲染输出标题 PNG，不与图片内容混排 |

### 执行要点

- 优先按「〇、环境能力探测」结果选路径：具备图像生成 → 路径 A；不具备 → 路径 B；两者皆无 → 文本降级。拿不准时默认直接生成图片（仅当已确认具备图像生成能力时）。
- **标题单独生成**：标题作为独立单元（单独一张标题图或独立文字层），不与图片内容混排；需要精确时单独用确定性渲染输出标题 PNG。
- 确定性渲染时，数据、标题、编号全部在源里写死并逐字核对，导出前后各检查一遍。
- 同一生成动作失败 2 次（数据被篡改 / 标题被替换 / 编号错位 / 整图重绘等）→ 停止换提示词重试，**切换渲染路径**（生成式图像失败改确定性渲染，HTML 异常则修正源文件）。
- 图文密集内容**禁止**用 image_edit 做局部微调；需要改动时改源文件后重新生成。

## 十一、最终质量检查

生成最终成品之前，检查：

- 是否完整理解了原始内容
- 是否保留了关键事实
- 是否改变了原始含义
- 是否产生了虚假信息
- 是否存在明显重复
- 是否存在信息层级混乱
- 是否存在过多文字堆积
- 是否存在无意义装饰
- 是否存在视觉重点不明确
- 是否能够通过快速浏览理解核心内容
- **标题是否单独成单元、是否与内容清晰分离**

如果发现问题，在生成最终结果之前自行修正。

## 最终要求

不要输出：分析过程、设计说明、Prompt、方案解释、制作步骤、为什么这样设计。

不要给用户选择方案。不要询问用户问题。直接根据输入内容完成最终视觉成品。

最终结果应该是一份已经完成设计、已经完成信息整理、已经完成视觉层级、可以直接阅读和使用的成品。

核心原则：内容决定结构。信息关系决定层级。层级决定视觉权重。视觉服务于理解。不要让设计凌驾于内容。
