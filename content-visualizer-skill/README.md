# Content Visualizer（内容视觉化）

把用户发来的原始内容**直接变成**一张设计完成、可直接阅读和呈现的视觉成品（信息图 / 视觉海报 / 长图 / 配图封面）的 Agent Skill。

> 不是总结内容，也不是解释内容，而是将内容本身转化为视觉作品。用户不参与中间设计过程，直接交付成品。

## 功能特性

- 输入文章 / 笔记 / 要点 / 数据 / 报告片段，一键输出成品图片（PNG）
- 自动完成：内容理解 → 信息提取 → 信息关系判断 → 内容重组 → 信息层级建立 → 标题生成（单独）→ 版式设计 → 视觉设计 → 成品生成
- 画面中的所有数据、比例、数量、时间、人物、引用与结论均来自用户原文，严格禁止编造或补充原文没有的事实与数字
- 不向用户询问结构 / 版式 / 配色 / 风格，不让用户选择方案，直接交付成品
- **跨平台自适应**：生成前先探测当前模型可调用的模态能力（图像生成 / 网页渲染 / 文件交付），自动选择可行的生成路径，不绑定单一平台专属工具名

## 核心原则

1. 内容决定结构
2. 信息关系决定层级
3. 层级决定视觉权重
4. 视觉服务于理解

## 安装

将 `content-visualizer` 整个文件夹放入 Agent 的 skills 目录即可：

- 若 Skill 管理器按目录扫描：把本目录直接放到 skill 根目录（如 `.skills/`、`skills/`、`.user_skills/` 等）
- 若需要压缩包：使用仓库中的 `content-visualizer-skill.zip` 解压后放置

> 提示：请把本文件夹放到 Agent 可识别的 Skill 根目录下（不同平台目录名可能不同），并确保目录名保持 `content-visualizer`。

## 使用方法

用户以 `/生成导图` 命令开头（或消息中包含该命令），并附上一段需要做成图的原始内容：

```
/生成导图
（要视觉化的原始内容：文章 / 笔记 / 要点 / 数据 / 报告片段等）
```

命令与内容可以在同一条消息里，也可以分开发；只要消息中包含 `/生成导图` 命令，就会命中本 Skill。

最终产出视觉成品（图片 PNG），并通过 `present_files` 交付。

## 工作原理简述

收到内容后，Skill 按以下工作流执行：

```
读取输入 → 环境能力探测 → 不确定问题人工确认核对 → 内容理解 → 信息提取 → 信息关系判断 → 内容重组
→ 信息层级建立 → 标题生成（单独）→ 版式设计 → 视觉设计 → 文字处理
→ 方案选型（按能力探测结果选择路径）→ 成品生成 → 质量检查 → 交付
```

其中标题采用「第一性原则」六步法单独生成：降维换喻 → 配动作对 → 制造落差 → 抽走主体 → 语法留白 → 悬念收口。

生成前会先探测当前环境的模态能力，自动选择路径：具备图像生成能力 → 直接生成图片（如豆包 `image_gen` + `seedream_5.0_pro`）；无图像生成但具备网页渲染 → 确定性渲染兜底（HTML/SVG → 截图 PNG）；纯文本环境 → 直接生成文本成品（Markdown 排版），不做图片编辑。

详细规则见 `SKILL.md` 与 `references/` 目录。

## 目录说明

| 文件 | 作用 |
| --- | --- |
| `SKILL.md` | Skill 主文件：角色定位、触发方式、调用格式、环境能力探测、执行步骤、标题生成原则、铁律、参考索引 |
| `references/workflow.md` | 详细工作流：环境能力探测、不确定问题确认、内容理解、信息重组、信息提炼、标题生成、信息层级、版式设计、视觉设计、文字处理、视觉阅读路径、方案选型、最终质量检查（动手前必读） |
| `references/prompt-guide.md` | 渲染路径实施指南：路径 A 直接生成图片（默认）、路径 B 确定性渲染兜底、文本交付降级、路径选择速查 |

## 跨平台兼容性

本 Skill 被设计为**可跨平台复用**，不绑定单一平台专属工具名：

| 运行环境 | 可用路径 | 说明 |
| --- | --- | --- |
| 具备图像生成能力（如豆包 / 扣子等） | 路径 A 直接生成图片 | 原生体验最佳，直接输出 PNG |
| 无图像生成、具备网页渲染 + 文件交付 | 路径 B 确定性渲染 | HTML/SVG 精确排版 → 截图 PNG |
| 两者皆不具备 | 文本交付降级 | 直接生成文本成品（Markdown 排版），不做图片编辑 |

工具名一律按当前环境实际可调用的能力识别，禁止编造不存在的工具。
